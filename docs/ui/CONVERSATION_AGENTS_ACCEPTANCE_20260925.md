# 会话 Agent 首批交付与验收（2026-09-25）

本批沿用 2026-09-22 报告的先后次序，先打通组织群聊中的明确 Agent 调用与结果回传。不是六个阶段全部完成，也不是生产或商业验收。

## 已实现

- 原有组织群聊加入独立 Agent 成员；可添加多个，分别由人明确调用，不自动互相唤醒。
- Agent 固定引用已发布 Workflow 版本。每次调用创建隔离的 Session 和 Run，保留真实调用人、源消息和会话关联。
- 只把用户明确选择的一条消息交给 Agent；加入前的历史、另一成员的模型会话不会自动共享。
- 同一 Agent 和源消息的并发重试返回同一 Run。执行权限仍按当前 Workspace 校验。
- 终态回复与 Run 状态在同一数据库事务内持久化。失败不向群成员公开内部错误。移出 Agent 后不再回传后续结果。
- 群聊显示执行/待审批状态，进入现有真实审批入口。运行详情根据后端可见关联返回原群聊。
- 新加入的成员看不到早先请求产生的 Agent 回复；组织普通成员可以读显式共享的回复，但不能因此访问 Workspace 运行详情。
- 本轮真实测试发现并修复工具轮次丢弃 reasoning_content 的适配问题；追加事件保留模型所需上下文，重建时合并同一次完成中的文本与 tool_calls。

## 3000 环境实际记录

组织：E2EAdmin 的组织。群聊「人机协作联测 20260925」：
`01a0d70e-7b18-742a-819b-9e681d1f60c1`。

使用一个真实浏览器和独立的普通成员 API 会话进行联测，没有宣称两个独立浏览器持续在线。

1. 普通成员发送限定测试消息，E2EAdmin 在界面中预览、选择「需求讨论助手」并确认调用。
2. Run `01a0d714-e938-7670-ae9a-da7fff5fcec8` 真实模型成功回复「人机协作联测成功」，自动回到原群。
3. 独立普通成员确认可读该回复，但读取 Workspace Run 详情返回 403。并发重放调用返回同一 Run；缺少幂等键返回 400。
4. 「需求整理助手」调用现有需要执行确认的只读工具，Run `01a0d716-ae65-706d-a823-3578c93b7294` 进入等待审批。界面拒绝后恢复，但模型第二轮返回 400。失败提示正确回群；该历史失败保留，不作为成功验收。
5. 模型适配层修复部署后，以新消息创建 Run `01a0d723-8cb9-7307-b5e2-1efecda2696f`。它进入等待审批，界面拒绝后恢复，最终成功回复「已尊重审批决定，协作闭环完成」，自动回到原群。实际领取执行 2 次；审批记录为拒绝，工具调用为 denied，未执行被拒绝的工具。模型所需上下文已持久化。
6. 运行详情的「返回原群聊」已实际点击验证。普通成员仍可读共享回复，但读取运行详情和发起 Workspace Agent 调用均返回 403。

证据位于 `.zeus/evidence/conversation-agents-20260925/`，不包含登录凭据或原始模型推理内容。其中 `approval-resume.json` 记录最终审批恢复结果，`group-approval-resumed.png` 保存回群成功页面，`peer-verification.json` 记录普通成员权限验证。
