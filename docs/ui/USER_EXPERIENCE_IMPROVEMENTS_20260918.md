# 用户体验报告改进：2026-09-18

对应本地实测报告 `.zeus/evidence/user-audit-20260918/report.md`。

## 聊天、确认与执行

- 聊天资源工具默认返回 `proposed`，不创建 WorkItem 或 Workflow。预览仍走原有租户、成员、fence、工具授权和审批检查，工具结果保存在 Session Event。
- 用户可编辑预览并确认创建。Web 从真实 Run 的工具事件读取草稿，拒绝伪造的草稿 ID；工作项确认复用草稿 ID 作为幂等键。
- 明确启用“允许本轮直接创建”时，Run 输入使用 `studio_resource_mode=create`。此选择不会继承到下一轮，也不会授予发布或执行权限。默认值与缺失值均为预览，模型工具参数不能改变该选择。
- 既有聊天 Agent 无须重新发布即可使用服务端预览边界。运行时补充真实状态说明，区分待确认、待处理和未发布；已有记录及 Agent 版本不改写。
- 聊天创建的工作项可以关联到原对话。普通“发送”只继续聊天流程；独立“开始执行工作项”入口要求明确选择工作流和填写执行要求，业务结果、审批及验收入口回到关联对话中。
- 原有工作项执行 Run 仍使用单独执行 Session；界面关联展示，不混用聊天流程和业务流程的工具权限。
- 默认收起技术连接状态、Run 状态码和事件数；同步中断仍显示重连入口。原始证据在执行详情中保留。

## IM 与导航

- 私聊仅选择一个成员，不要求会话名称；群聊仍需名称与成员。
- 未选择有效成员时禁用创建。通讯录没有其他成员时，Organization Owner 可查看成员名单，并明确提示当前页面尚不支持发送邀请；其他成员获得联系管理员提示。
- 四模块导航在较窄窗口仍可见；顶部新建工作项只出现在业务区域。
- Agent 配置和聊天助手设置归入 Management Terminal，流程、定时任务、触发器归入 Business Studio。统一面包屑及导航选中状态。
- 工作项长描述折叠，状态、负责人和下一步更容易看到；首页突出继续聊天、待审批和已完成运行。

## 验证边界

单元测试覆盖工具结果与模型文本区分、草稿来源、确认幂等键、普通发送不切入业务执行，以及显式创建开关。真实 PostgreSQL 覆盖默认预览零资源写入、显式创建、重试与现有授权门禁。UI 的多用户实时 IM、完整读屏与负载验收仍需独立记录，不能由上述检查替代。
