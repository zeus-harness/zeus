# 任务入口与处理界面首版简化

日期：2026-10-01。部署范围：Mac 本地隔离 E2E，`http://127.0.0.1:3100`。3000 日常环境保持原状。已有未提交修改保留；没有推送或外网发布。

## 改版前实际观察

在原演示的独立 Google Chrome for Testing 窗口查看并保存截图，未使用 DiffScope 的浏览器或目录。

1. 聊天页同一工作项已运行成功，上方仍标“已保存，未自动执行”。聊天助手未配置时发送按钮不可用，而已发布工作流程可以执行，两个入口的区别不清楚。
2. 首页有 Studio/Terminal 四个模块及七个技术对象，另有开始对话、继续聊天、新建工作项等并列入口。只统计分配给自己的任务，因此用户刚创建但未分配的目标被遗漏。
3. 任务页同时出现工作项、运行、验收三个状态，启动表单、状态编辑、结果及验收分散，用户需跳到 Run 页面处理审批。
4. IM 页在没有会话时也占用三个区域，成员/Agent 管理与聊天竞争注意力。实际 IM 是组织成员会话，保留其成员访问能力，不能整体改成仅管理员配置。

## 实现

- 主导航使用工作台、任务、审批、团队消息。工作流、运行、经验、定时和触发器在高级工具；设置中心按既有权限提供工作空间、组织、Agent、模型及平台入口。
- 首页展示最近更新的 20 项团队任务，包含未分配目标。每项读取关联尝试和验收，区分等待审批、失败需要处理、待验收、待验证及已归档；读取失败显示未知进度。首页一个主要发起任务入口。
- `/:workspaceId/new` 用目标输入开始任务，执行方式默认选择已有已发布流程，可展开核对和更改。执行遵循原 Agent/模型/审批配置，不自动授予工具权限。独立目标与首次执行使用稳定去重键，部分成功/响应丢失后保留原输入并提供已保存任务入口。
- 默认任务详情统一当前进度、待执行具体内容、批准/拒绝、失败重试、最新结果、人工验收、修改意见再次处理与验证归档。后台从持久记录刷新，等待不依赖聊天页常驻。技术记录折叠，历史结果选择和原编辑能力保留在完整页面。
- 目标版本改变使旧验收在界面上失效；可更新验收决定。审批、结果接受、归档分别保存。只展示最新根运行结果，不将较早成功结果替代最新失败。
- 团队消息保留组织会话及群消息交给 Agent 的能力，会话成员和 Agent 管理放入折叠设置。未选择会话时只展示会话列表和消息区域。
- 沿用 `@zeus/ui` 组件、颜色和间距，使用系统正文字体、已有圆角 token、一致焦点环及移动端按钮尺寸。代码内容保留等宽字体，没有初始化新组件系统。

核心文件：`AppShell.svelte`、Workspace 首页、新增 `new` 路由、`TaskWorkspace.svelte`、`task-state.ts`、`task-launch.ts`、`task-attempt.ts`，以及现有工作项、会话和设置页面。新增 helper 只包装现有领域 API；本轮没有新增 Rust/数据库协议或迁移。

## 边界

四阶段进度是持久业务记录的呈现，不是新增 BPM/DAG 执行引擎。模型和工具为现有确定性模拟模型与 `builtin.echo`。没有真实 Slack/Lark 消息、远程 push/merge/tag、部署或 SQL 修改；不能据此宣称生产隔离、真实问题修复、外部适配器及 H/I5 已验收。H/I5 仍为 active。

工作台最近 20 项、任务详情最近 50 次尝试保持有界读取；完整列表仍支持游标。连续对话继续使用既有助手讨论能力，首次目标输入与既有已发布执行流程连通，聊天助手配置不自动改变。下一步可基于用户体验继续调整日常文案/密度，并独立实现外部适配器、实际成功证据和 SQL/deploy 专门审批。
