# 组织群聊中的 Agent

## 当前交付范围

在原有组织群聊中增加独立 Agent 成员。成员身份固定引用一个已发布 Workflow 版本，实际执行仍使用原有 Session、Run、工具审批及追加事件。旧的人际消息和个人 Agent Studio 保持兼容；个人 Studio 历史迁入统一会话尚未实现。

会话负责人在群聊右侧「Agent 成员」选择当前 Workspace 的已发布流程，添加其 Agent。每个群最多 8 个 Agent 成员。调用者必须在该 Workspace 拥有 OperateRun 权限；组织成员身份不授予此权限。

在 Agent 加入后的一条人类消息下选择「交给 Agent」，预览原消息并确认结果共享。后端读取消息，不接受客户端伪造的消息正文或执行 Workspace。仅这一条消息进入新建的独立 Session，不自动带入群聊历史，不复用其他成员的模型上下文。

调用窗口默认勾选「创建持久工作项」。后端在同一事务内从源消息创建目标，并把工作项、Session 和 Run 关联；群聊提供工作项与验收入口。API 的 `create_work_item` 默认为 false，兼容既有仅回复调用。

同一 Agent 成员与源消息只创建一次首 Run 和工作项，使用 `Idempotency-Key: im:<agent_member_id>:<source_message_id>`；相同 key 改变创建工作项选项会冲突。有关联工作项的失败 Run 可以在运行页「创建重试 Run」，目标不变，每次尝试独立留痕。需要修改的成功结果可在工作项页写入人工意见并「按此意见重新处理」。只有首调用自动回传群聊；后续尝试在工作项页跟踪。未关联工作项的聊天失败仍从新消息调用。Agent 回复不会触发另一个 Agent，暂不支持自主循环或后台观察。

执行时 WorkItem/Workflow 创建工具固定为 preview。此阶段没有群内草稿确认入口；不要把模型回答中的建议当作已创建资源。工具审批通过「Agent 调用与审批」中的运行详情入口处理，仍校验真实决策者资格；聊天“同意”和 @ 不是授权。

## 数据和权限

迁移 `0042_conversation_agents.sql` 增加：

- `im_agent_members`：组织会话中的 Agent 身份、固定流程版本、Workspace、加入消息边界和移出时间。
- `im_agent_runs`：源消息、Agent 成员、真实调用者与 Run 的持久关联。
- `im_messages.sender_agent_id / agent_run_id`：明确区分人类和 Agent 消息；不伪造人类 sender。

新表启用强制 RLS。组织范围的读取不能隐式读取 Workspace Run 的参数、工具痕迹或原始错误。群成员可以读取显式分享的最终回复以及有限的调用状态；运行详情继续受 Workspace 权限保护。

事务锁序列化会话成员变更、调用去重与结果写入。Run 进入终态的同一事务将一条回复写回会话，重启后不依赖浏览器补写。结果最多展示 10000 字符，完整结果由有权成员在 Run 详情查看。失败仅返回固定提示，不向群成员公开内部异常。

结果读取同时要求成员有权看到源消息。源消息发出后才加入的用户，即使在 Run 完成前加入，也不能通过结果泄露早先消息。Agent 只接受自己加入边界之后的人类消息。

Agent 移出，或调用者退出会话、失去有效组织/Workspace 身份后，不再向会话投递结果。移出 Agent 不等价于取消已有 Run；取消仍使用已有执行权限和 Run 取消入口。跨组织、平台支持身份、服务账号不能借此读取会话。

## 模型工具轮次恢复

本轮真实审批联测发现 DeepSeek 在恢复后的工具轮次返回 400。原适配器未接收 `reasoning_content`，并把同一次完成中的文本与 tool_calls 拆成两个模型消息。

修复后，流式片段完整累积该可选字段，写入追加的 assistant_message 事件；`tool_calls_follow` 标记同一次完成，Session 重建将其与随后的工具调用合并，模型适配器按原值回传。群聊最终回复仍只使用最终 content，不把该字段作为聊天消息展示。普通 OpenAI-compatible 模型未提供该字段时不会伪造它。

历史已丢失的字段不能补造；此类失败记录保留，需要从新消息发起新调用。不要将旧事件原地改写以伪装历史成功。

协议依据：[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。实际是否修复必须以新的真实工具/审批轮次验收，不以协议文档代替执行证据。
