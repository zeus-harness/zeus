# 执行确认与权限申请

Agent Studio、运行详情和审批中心使用同一份持久审批记录。

- 执行确认（`execution`）：由运行发起人确认具体工具及参数。发起人需要仍是有效的 Workspace Owner、Builder 或 Operator。Owner 不能代替另一位发起人确认。
- 权限申请（`resource_access`）：用于 Workspace Owner 标记为受限的工具。当前由该 Workspace 的真实 Owner 成员审批，不使用组织角色、职位名称或平台支持权限代替资源授权。
- 历史工具审批（`legacy_tool`）：旧记录继续按原 Owner/Operator 策略处理。
- 两类审批均要求真实用户；服务账号不能代替人审批。子任务继承父运行的发起人。

## 配置与操作

在 **Workspace 设置 → 工具配置 → 受限工具授权** 开启“需要资源授权”。API 对应 Workspace Capability 的 `policy.resource_authorization_required` 布尔值，更新需要 Owner 权限和 `If-Match`。

受限工具仍须启用且被发布的 Workflow 允许。运行请求调用时先挂起并生成权限申请。Owner 填写理由批准后，系统生成独立的执行确认，等待发起人处理；第二次确认后才恢复执行。拒绝会生成配对的工具结果，交回 Agent 处理。

授权只覆盖本次 Run、工具调用和完整参数，有效期不超过 1 小时或原等待期限。恢复执行前检查授权有效性、撤销状态、发起人和授权人当前成员关系、工具与绑定版本。参数、工具配置或绑定发生改变后，旧授权不能继续使用。

审批中心可撤销尚未开始执行的授权；撤销会取消待确认操作、生成拒绝结果并唤醒 Run。不能用撤销按钮回滚已经开始的副作用。每次决定及撤销均保留审计记录。

等待沿用现有持久 Run 挂起机制，释放执行租约；数据库记录仍会保存。

## 当前范围

这是 Zeus 内部的 Workspace 工具使用授权，不自动修改 GitHub、数据库、云平台等外部 IAM，也不允许访问其他租户、禁用工具或 Workflow 未声明的工具。当前没有企业汇报线或任意资源负责人目录，Workspace Owner 是明确的授权主体。无真实发起人的自动运行不能自行完成人工执行确认。

审批与 WorkItem 的人工结果验收保持独立。历史审批和已发布 Workflow 不自动改写。
